# 所有者一次性审阅指南

统一入口：[PR #2](https://github.com/Sherry1213184/Vita-Kitchen/pull/2)，目标分支 `main`。它包含第一、第二、第三轮的完整改动；PR #1 被此 PR 替代，不再需要单独合并。保留每轮 Git 提交和 CHANGELOG，方便按轮检查。

## 每轮带来了什么

| 轮次 | 使用上的变化 | 主要检查位置 |
| --- | --- | --- |
| 第一轮 | 手机点菜单快捷入口；个人历史翻页；厨房待处理筛选；重复下单和状态冲突保护 | `lib/orders.ts`、`app/kitchen.tsx`、订单测试 |
| 第二轮 | 活动日期/地点/行程与报名；默认 GBP 的均分账本；待付/待收、结清/撤销与作废保留；账单关联活动 | `lib/community.ts`、`lib/community-money.ts`、`components/community.tsx`、迁移 0003 |
| 第三轮 | 日期/目的地实名多选投票，改票/撤回/结束/重新开放；照片与小记、同行朋友、作者编辑、更多历史回忆；从活动进入投票/回忆 | `lib/social.ts`、`components/social.tsx`、图片读取接口、迁移 0004 |

## 建议的验收顺序

1. 按 README 在本地安装、构建并应用尚未执行的迁移。启动后使用本地模拟登录，在“我的资料”保存昵称。
2. 点一份菜，在厨房依次更新状态，确认取餐；检查手机底部入口和个人历史翻页。
3. 发起活动并报名。记一笔 GBP 开销，核对垫付人、分摊人、尾差、待付/待收；结清后再撤销，检查金额恢复。
4. 从活动进入“投票 / 留回忆”。新建两个日期选项，多选后保存、改票，再结束/重新开放；注意投票不自动修改活动日期或报名。
5. 在回忆墙保存照片、小记和同行朋友，检查日期、照片放大及作者编辑。换另一个本地测试身份确认不能编辑他人回忆。
6. 未登录访问新增接口或回忆图片，应返回 401；未关联到记录的图片键不能读取。

自动验证：`pnpm run typecheck`、`pnpm test`（28 项）、`pnpm run build`。测试在内存 SQLite 中按顺序执行全部迁移，使用本地照片模拟存储，不连接生产数据库。

## 发布前需要确认

- 第一轮没有新增迁移。第二轮追加 `0003_confused_prism.sql`，第三轮追加 `0004_fair_doctor_strange.sql`；共新增 7 张表，历史迁移、原订单/菜单/资料表保留。
- 先备份生产 D1/R2，核对已应用的迁移边界；由有原 Sites 项目权限的所有者按平台流程发布。不要重复执行已应用的迁移。
- 原 `.openai/hosting.json` 的 project_id、D1/R2 绑定及邀请制不变；没有新增依赖或外部服务。GitHub 合并不会自动发布。
- 所有获邀成员共享活动、账本、投票和回忆；报名和投票只代表本人，回忆仅作者可编辑。不要将 Sites 访问范围改成公开而继续使用此共享权限模型。
- 账本只作记录，不收款、不自动换汇；投票选项发布后固定；每条回忆最多一张 5MB 图片，更多照片可新建记录。
- 回忆按发布顺序，每次加载 20 条；活动/投票/账本仍面向小圈子一次加载。暂不提供相册批量导入、评论或通知。
- D1 与 R2 不能跨存储事务：上传成功但数据库写入失败时不会公开该图片，原请求重试会复用图片键；不自动删除存储对象来处理不确定的提交结果。
- 创建请求标识在当前表单会话保留。网络异常后先重试或刷新核对已有记录，再重新创建，避免把同一次记录当作新的内容。

审阅通过后，只需合并 PR #2。发布与回退细节见 [release.md](release.md)。
